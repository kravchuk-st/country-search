# Архитектурные решения

Живой поиск стран по имени через `GET https://countries.dev/name/{query}`. В этом документе объясняются решения,
стоящие за обработкой запросов, а не за вёрсткой.

## 1. Отмена устаревших запросов

### Проблема

Если пользователь набрал `sp`, а затем `spain`, ответ на `sp` может прийти позже ответа на `spain` и перезаписать
правильный результат более старым. Без явной отмены это вопрос времени, а не «если».

### Как это работает

- `createSearchController` (`src/searchController.ts`) владеет ровно одним `AbortController` для текущего запроса
  (`activeRequest`).
- `input()` вызывает `cancelActiveRequest()` **при каждом нажатии клавиши**, ещё до того, как debounce начнёт отсчёт.
  Отмены только в момент срабатывания debounce недостаточно: пока debounce ждёт, предыдущий ответ может прийти и
  отрисоваться под новым текстом.
- `runSearch()` создаёт новый `AbortController` на каждый запрос и передаёт его `signal` в `searchCountries`.
- `searchCountries` (`src/searchCountries.ts`) объединяет сигнал вызывающего с `AbortSignal.timeout(timeoutMs)` через
  `AbortSignal.any`, поэтому один сигнал покрывает обе причины остановки: вызывающий отменил запрос (`AbortError`)
  или сервер отвечает слишком долго (`TimeoutError`).
- `fetch` отклоняет промис сразу после `abort()`, поэтому код устаревшей ветки (отрисовка результатов) вообще не
  выполняется.

### Почему не просто игнорировать устаревшие ответы флагом или временной меткой

- Запрос продолжает выполняться: он по-прежнему занимает трафик, батарею и слот соединения (браузеры ограничивают
  число параллельных соединений на хост), а сервер продолжает выполнять работу. `abort()` останавливает запрос у
  источника, и в Network он отображается как `canceled`.
- Флаг приходится проверять во всех местах, которые трогают состояние, и стоит забыть одну проверку, как баг
  возвращается. С отменой забывать нечего: отменённый запрос не может вызвать обработчик.
- В `runSearch` есть одна дополнительная защита (`if (request.signal.aborted) return`). Она основана на том же
  `AbortSignal`, это не отдельный флаг, и она страхует от транспорта, который не учитывает `abort()`. Это страховка, а
  не основной механизм.

### Как различаются три исхода

`classifyError` (`src/classifyError.ts`) превращает любое выброшенное значение в одно из четырёх:

| Что выброшено                         | Результат   | Что видит пользователь               |
| ------------------------------------- | ----------- | ------------------------------------ |
| `AbortError` (мы сами отменили)       | `cancelled` | ничего: это не ошибка                |
| `TimeoutError`                        | `timeout`   | сообщение об ошибке и кнопка «Retry» |
| `HttpError` (не 2xx и не 404)         | `http`      | сообщение об ошибке и кнопка «Retry» |
| всё остальное (например, `TypeError`) | `network`   | сообщение об ошибке и кнопка «Retry» |

`404` до `classifyError` не доходит: `countries.dev` отвечает 404, когда совпадений нет, поэтому `searchCountries`
возвращает `[]`, а интерфейс показывает дружелюбное «ничего не найдено». `fetch` не бросает исключение на
HTTP-ошибках, поэтому `searchCountries` сам проверяет `response.ok` и выбрасывает `HttpError` (`src/httpError.ts`,
хранит `status`).

Ошибка распознаётся по `error.name`, а не по `instanceof DOMException`, потому что в некоторых окружениях выбрасывается
обычный `Error` с именем `AbortError`.

### Как это тестируется

`src/searchController.race.test.ts` подменяет `fetch` моком (`src/testing/pendingFetch.ts`), в котором ответ на более
ранний запрос приходит **после** ответа на более поздний. Мок отклоняет промис с `reason` сигнала при отмене запроса,
как настоящий `fetch`, поэтому тест отличает реальную отмену от «приложение просто проигнорировало ответ». Тест также
проверяет, что сигнал первого запроса действительно `aborted`.

## 2. Тайминги: debounce 300 мс, таймаут 8 с

### Debounce (`DEFAULT_DEBOUNCE_MS` в `src/searchController.ts`)

- **Без debounce (0 мс)** каждое нажатие клавиши отправляет запрос: `spain` — это пять запросов, из которых четыре
  сразу отменяются. Отмена сохраняет корректность экрана, но трафик, нагрузка на сервер и мерцание состояния
  загрузки — чистая трата.
- **Слишком долго (около 1 с)** страница ощущается сломанной: пользователь перестал печатать, а ничего не происходит.
- **300 мс** дольше паузы между нажатиями клавиш при непрерывном наборе и достаточно коротко, чтобы результат
  появлялся сразу после остановки. Значение вынесено в константу и может быть передано в `createSearchController`,
  что используют тесты (5 мс).

`debounce` (`src/debounce.ts`) написан вручную, как требует задание: он сбрасывает таймер при каждом вызове, поэтому
выполняется только последний вызов серии, с последними аргументами.

### Таймаут (`DEFAULT_TIMEOUT_MS` в `src/searchCountries.ts`)

8 секунд достаточно для медленного мобильного соединения и достаточно мало, чтобы зависший запрос превратился в
ошибку с кнопкой «Retry», а не в бесконечный спиннер.

## 3. Сложность

Пусть `L` — число языков страны, `C` — число валют, `N` — число стран в ответе.

| Функция                      | Время    | Память   | Примечание                                                            |
| ---------------------------- | -------- | -------- | --------------------------------------------------------------------- |
| `mapCountryResponse`         | O(L)     | O(L)     | один `map` по языкам, остальные поля копируются за O(1)               |
| `mapCountryDetails`          | O(L + C) | O(L + C) | использует `mapCountryResponse`; `borders` передаётся по ссылке       |
| отрисовка списка результатов | O(N · L) | O(N · L) | `createCard` вызывает `mapCountryResponse` один раз для каждой страны |
| `debounce` (на вызов)        | O(1)     | O(1)     | `clearTimeout` и `setTimeout`                                         |
| `SearchController.input`     | O(1)     | O(1)     | отмена, нормализация, планирование; плюс уведомление подписчиков      |

На практике `L`, `C` и длина `borders` — однозначные числа, поэтому маппинг по сути линеен по `N`. Бонус (кэш ответов и
дедупликация одинаковых запросов в полёте) не реализован.

## 4. Принципы чистого кода и где они применены

- **Единственная ответственность.** `debounce.ts` занимается только временем, `searchCountries.ts` — только сетью и
  смыслом HTTP-статусов, `classifyError.ts` — только классификацией ошибок, `mapCountryResponse.ts` и
  `mapCountryDetails.ts` — только преобразованием данных API в данные для интерфейса, `searchController.ts` — только
  состоянием поиска, `view.ts` — только DOM.
- **Логика не зависит от DOM.** В `searchController.ts` нет доступа к DOM, поэтому весь жизненный цикл запроса
  тестируется без браузера и без сети. `view.ts` получает контроллер аргументом (`createApp(controller)`), поэтому в
  тестах вместо настоящего передаётся заглушка.
- **Чистые функции.** `mapCountryResponse`, `mapCountryDetails` и `classifyError` не имеют побочных эффектов и не
  изменяют входные данные; для этого есть тест.
- **Невозможные состояния нельзя представить.** `SearchState` в `searchController.ts` — размеченное объединение
  (`idle | loading | results | empty | error`): например, только у `results` есть `countries`, и только у `error` есть
  `failure`. `switch` в `view.ts` обрабатывает каждый случай.
- **Ошибки явные.** `HttpError` — класс со `status` вместо строк или разбросанных по коду проверок кодов состояния.
- **Нет «магических» значений.** `DEFAULT_DEBOUNCE_MS`, `DEFAULT_TIMEOUT_MS`, `NO_VALUE` и словарь `ERROR_MESSAGES` в
  `view.ts` имеют имена.
- **Нет дублирования.** `mapCountryDetails` строится на `mapCountryResponse`.
- **Безопасная отрисовка.** Динамический текст устанавливается только через `textContent` (`el()` в `src/dom.ts`),
  картинки флагов используются только для `https:`-адресов, а правило ESLint (`no-restricted-properties` в
  `eslint.config.js`) запрещает `innerHTML` и `insertAdjacentHTML`.
- **Сначала тесты.** Для каждой обязательной функции есть коммит с падающими тестами (написанными по FIRST) раньше
  коммита с реализацией. Тест гонки запросов — отдельный коммит.

## Известные ограничения

- В API нет описания страны; описание в детальном виде генерируется из полей, которые API отдаёт (родное название,
  регион, субрегион, демоним).
- Границы показаны трёхбуквенными кодами стран, потому что именно их возвращает API.
- Нет кэша ответов и истории поиска.
- Тесты интерфейса запускаются в jsdom, а не в настоящем браузере.
